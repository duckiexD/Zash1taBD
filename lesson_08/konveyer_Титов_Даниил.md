## Письмо 1. Ревью конвейеров

### 1. Выручка доставленных заказов от ноутбуков.

- Решение: есть ошибка — условие на элемент массива проверено до $unwind — проходят заказы целиком — неверно
- Комментарий: Ошибка в порядке этапов. Фильтр по категории "ноутбуки" должен стоять до $unwind, чтобы сразу отсеять заказы без ноутбуков. Иначе $unwind развернет все товары, и фильтр по категории после разворота уже не сработает корректно, если в заказе есть и другие товары, или потребует дополнительных ресурсов.

### 2. Сколько заказов в пути в каждом городе.

- Решение: есть ошибка — $project перед стадией, которой нужно отброшенное поле — верно
- Комментарий: Этап $project удалил поле status, поэтому последующий $match не может найти ни одного заказа со статусом "в пути". Нужно либо добавить status: 1 в $project, либо (что правильнее) переставить $match на первое место, чтобы сначала отфильтровать нужные заказы, а потом уже отбрасывать лишние поля.

### 3. Номер первого по дате заказа каждого покупателя из трёх: c-007, c-011, c-018.

- Решение: есть ошибка — $first или $last без $sort перед $group — верно
- Комментарий: Чтобы $first выбрал заказ с самой ранней датой, необходимо добавить этап $sort по полю даты до этапа $group. Сортировка после $group сортирует уже готовый результат и не влияет на выбор первого документа.

### 4. Пять самых дорогих доставленных заказов.

- Решение: есть ошибка — стадии стоят не в том порядке: $limit срабатывает раньше отбора — верно
- Комментарий: Этап $limit стоит до $match. Из-за этого база сначала берет 5 самых дорогих заказов вообще, и только потом проверяет их статус. Нужно сначала отфильтровать доставленные заказы, затем отсортировать их и только после этого ограничивать количество.

### 5. Выручка доставленных заказов по способам оплаты.

- Решение: есть ошибка — путь к полю записан без знака $ — верно
- Комментарий: В этапе $group для группировки по полю необходимо использовать знак $ перед именем поля. Кроме того, для обращения к вложенному полю нужна точечная нотация: "$payment.method". Без знака $ база воспринимает строку как текстовое значение и группирует все заказы в одну группу.

### 6. Сколько штук смартфонов продано в доставленных заказах.

- Решение: есть ошибка — условие на элемент массива проверено до $unwind — проходят заказы целиком — верно
- Комментарий: После $unwind необходимо добавить еще один $match по категории "смартфоны", чтобы суммировать количество только смартфонов, а не всех товаров из заказов, где они были. Также, после разворота обращение к полю количества обычно идет как $qty, а не $items.qty.

### 7. Средний чек доставленных заказов в каждом городе, округлённый до рубля, по убыванию.

- Решение: есть ошибка — путь к полю записан без знака $ — неверно
- Комментарий: В этапе $group для группировки по полю необходимо использовать знак $ перед именем поля ("$delivery.city"). Без него база воспринимает строку как текстовое значение и группирует все заказы в одну общую группу, из-за чего мы теряем разбивку по городам.

### 8. Три самых продаваемых по штукам товара в доставленных заказах.

- Решение: есть ошибка — путь к полю записан без знака $ — неверно
- Комментарий: В этапе $group для группировки по названию товара необходимо использовать знак $ ("$items.title"). Без него база воспринимает строку как текст, и все товары объединяются в одну общую группу.
- Исправленный конвейер:

```js
[
  { $match: { status: "доставлен" } },
  { $unwind: "$items" },
  { $group: { _id: "$items.title", qty: { $sum: "$items.qty" } } },
  { $sort: { qty: -1, _id: 1 } },
  { $limit: 3 }
]
```

## Письмо 2. Сборка из стадий

### 1. Пять самых дорогих доставленных заказов: только номер и сумма, без _id, от дорогого к дешёвому.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { $sort: { total: -1 } },
  { $limit: 5 },
  { $project: { _id: 0, number: 1, total: 1 } }
])
```

- Решено, запусков: 1

### 2. Выручка доставленных заказов по городам: поле revenue, города по убыванию выручки.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { $group: { _id: "$delivery.city", revenue: { $sum: "$total" } } },
  { $sort: { revenue: -1 } }
])
```

- Решено, запусков: 1

### 3. Сколько штук товаров каждой категории продано в доставленных заказах: поле qty, категории по убыванию qty.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { $unwind: "$items" },
  { $group: { _id: "$items.category", qty: { $sum: "$items.qty" } } },
  { $sort: { qty: -1 } }
])
```

- Решено, запусков: 1

### 4. Доставленные заказы по суммам чека: корзины до 50 000, от 50 000 до 200 000 и от 200 000 до 500 000, в каждой — число заказов в поле count.

```js
db.orders.aggregate([

```

### 5. Для каждого города — номер и сумма самого дорогого доставленного заказа (поля number и total), города по убыванию total.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { $sort: { total: -1 } },
  { $group: { _id: "$delivery.city", number: { $first: "$number" }, total: { $first: "$total" } } },
```

## Письмо 4. Свои конвейеры

### 1. Доставленные заказы по способу доставки: _id — способ (delivery.type), orders — число заказов, revenue — выручка. По убыванию revenue.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { 
    $group: { 
      _id: "$delivery.type", 
      orders: { $sum: 1 }, 
      revenue: { $sum: "$total" } 
    } 
  },
  { $sort: { revenue: -1 } }
])
```

- Результат совпадает с нужным, запусков: 1

### 2. Коллекция products. Средняя цена товаров каждой категории, округлённая до рубля: _id — категория, avg — средняя цена. По возрастанию avg.

```js
db.products.aggregate([
  { $match: {} }, 
  { 
    $group: { 
      _id: "$category", 
      avg: { $avg: "$price" } 
    } 
  },
  { 
    $project: { 
      avg: { $round: ["$avg", 0] } 
    } 
  },
  { $sort: { avg: 1 } }
])
```

- Результат совпадает с нужным, запусков: 1

### 3. Покупатели, у которых сумма доставленных заказов больше 400 000: _id — customer_id, spent — сумма. По убыванию spent.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { 
    $group: { 
      _id: "$customer_id", 
      spent: { $sum: "$total" } 
    } 
  },
  { $match: { spent: { $gt: 400000 } } },
  { $sort: { spent: -1 } }
])
```

- Результат совпадает с нужным, запусков: 1

### 4. Для каждого города — массив номеров отменённых заказов по возрастанию номера: _id — город, numbers — массив. Города по алфавиту.

```js
db.orders.aggregate([
  { $match: { status: "отменён" } },
  { $sort: { number: 1 } },
  { 
    $group: { 
      _id: "$delivery.city", 
      numbers: { $push: "$number" } 
    } 
  },
  { $sort: { _id: 1 } }
])
```

- Результат совпадает с нужным, запусков: 1

### 5. Одним запросом по доставленным заказам: в поле total — массив из одного документа { orders: число заказов }, в поле top — три товара с наибольшим числом штук (_id — название, qty — штуки), по убыванию qty, при равенстве — по названию.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  {
    $facet: {
      total: [
        { $count: "orders" }
      ],
      top: [
        { $unwind: "$items" },
        { 
          $group: { 
            _id: "$items.title", 
            qty: { $sum: "$items.qty" } 
          } 
        },
        { $sort: { qty: -1, _id: 1 } },
        { $limit: 3 }
      ]
    }
  }
])
```

- Результат совпадает с нужным, запусков: 1
